# 第三题 CAN 通信开发文档

## 1. 项目目标

使用两块 STM32F103C8T6 开发板模拟 CAN 通信。

主机连接按键，从机连接 LED。主机检测到按键按下后，通过 CAN 总线发送 1 字节数据 `0x11`；从机收到 `0x11` 后翻转 LED 状态，并返回 1 字节数据 `0x22`；主机收到 `0x22` 后通过 USART1 输出到串口助手。

## 2. 硬件连接

### 2.1 主机

- 按键：PB5
- USART1_TX：PA9，连接 TTL 模块 RX
- CAN_RX：PA11
- CAN_TX：PA12

### 2.2 从机

- LED：PB6
- CAN_RX：PA11
- CAN_TX：PA12

### 2.3 CAN 总线

两块开发板都需要外接 CAN 收发器。

连接方式：

```text
主机 PA12 -> 主机 CAN 收发器 TXD
主机 PA11 <- 主机 CAN 收发器 RXD

从机 PA12 -> 从机 CAN 收发器 TXD
从机 PA11 <- 从机 CAN 收发器 RXD

主机 CANH <-> 从机 CANH
主机 CANL <-> 从机 CANL
主机 GND  <-> 从机 GND
```

CAN 总线两端需要终端电阻。两节点总线断电后，CANH 与 CANL 之间通常应约为 `60 Ω`。

## 3. CubeMX 配置

### 3.1 GPIO

PB5 配置为输入，并开启上拉：

```c
GPIO_InitStruct.Pin = SWITCH_Pin;
GPIO_InitStruct.Mode = GPIO_MODE_INPUT;
GPIO_InitStruct.Pull = GPIO_PULLUP;
```

PB6 配置为推挽输出：

```c
GPIO_InitStruct.Pin = LED_Pin;
GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_PP;
```

### 3.2 USART1

USART1 用于主机串口输出：

```text
波特率：115200
数据位：8
校验位：None
停止位：1
```

### 3.3 CAN

CAN 波特率配置为 `500 kbit/s`。

最终使用的时序配置：

```text
Prescaler = 9
TimeSeg1 = 6 TQ
TimeSeg2 = 1 TQ
SJW = 1 TQ
```

采样点：

```text
(1 + TimeSeg1) / (1 + TimeSeg1 + TimeSeg2)
= (1 + 6) / (1 + 6 + 1)
= 87.5%
```


## 4. 软件结构

项目使用模块化方式拆分 CAN 通信代码。

主要文件：

```text
Core/Inc/can.h
Core/Src/can.c
Core/Src/main.c
```

`can.h` 中定义 CAN 通信 ID 和数据：

```c
#define CAN_ID_COMMAND      0x101U
#define CAN_ID_RESPONSE     0x102U
#define CAN_DATA_COMMAND    0x11U
#define CAN_DATA_RESPONSE   0x22U
```

其中：

- `0x101` 是主机发送命令帧 ID
- `0x102` 是从机返回响应帧 ID
- `0x11` 是主机发送的数据字节
- `0x22` 是从机返回的数据字节

## 5. 通用 CAN 函数

`can.c` 中实现了通用 CAN 通信函数：

```c
HAL_StatusTypeDef CAN_Start(void);
HAL_StatusTypeDef CAN_SendByte(uint16_t standard_id, uint8_t data);
bool CAN_ReadByte(uint16_t *standard_id, uint8_t *data);
```

### 5.1 CAN_Start

用于配置 CAN 滤波器并启动 CAN 外设。

### 5.2 CAN_SendByte

用于发送标准帧，数据长度为 1 字节。

### 5.3 CAN_ReadByte

用于轮询读取 CAN FIFO0 中的 1 字节数据。

## 6. 主机逻辑

主机编译配置为：

```text
Debug-Master
```

主机逻辑：

1. 初始化 GPIO、CAN、USART1
2. 启动 CAN
3. 轮询 PB5 按键
4. 检测到按键按下后发送 `0x11`
5. 轮询 CAN 接收 FIFO
6. 收到从机返回帧后，将收到的数据通过 USART1 发送到串口助手


## 7. 从机逻辑

从机编译配置为：

```text
Debug-Slave
```

从机逻辑：

1. 初始化 GPIO、CAN、USART1
2. 启动 CAN
3. 轮询 CAN 接收 FIFO
4. 只有收到 `ID = 0x101` 且数据为 `0x11` 时，才执行响应
5. 翻转 PB6 LED 状态
6. 返回 `ID = 0x102`、数据 `0x22`

其他 CAN 帧会被忽略。

## 9. 测试现象

正常通信时：

1. 按下主机按键
2. 主机发送 CAN 数据 `0x11`
3. 从机收到 `0x11`
4. 从机 LED 翻转
5. 从机返回 `0x22`
6. 主机串口输出原始字节 `0x22`

如果串口助手以十六进制显示，应看到：

```text
22
```

## 10. 调试过程记录

### 10.1 串口显示问题

最初串口输出为字符串，例如：

```text
TX: 0x11
```

在十六进制显示时会看到：

```text
54 58 3A 20 30 78 31 31 0D 0A
```

这是 ASCII 字符串，不是原始 CAN 数据。

最终修改为：主机收到 `0x22` 后，USART1 直接发送单字节 `0x22`。

### 10.2 回环测试

为了排查主机内部 CAN 控制器是否正常，曾增加 `Debug-Loopback` 配置进行单板回环测试。

回环测试用于证明：

- 按键检测正常
- USART1 输出正常
- CAN 控制器内部发送和接收正常

但回环测试不经过外部 CAN 收发器，不能证明外部 CAN 总线接线正常。

### 10.3 采样点问题

最初 CAN 配置虽然也是 `500 kbit/s`，但采样点约为 `50%`，实际通信不稳定。

修改采样点后通信恢复正常，说明主要故障原因是 CAN 位时序采样点不合理。

最终采用：

```text
Prescaler = 9
TimeSeg1 = 6 TQ
TimeSeg2 = 1 TQ
Sample Point = 87.5%
```

## 11. 注意事项

- 两块开发板必须共地
- CANH 必须连接 CANH，CANL 必须连接 CANL
- 两块开发板都需要 CAN 收发器
- 主机和从机必须使用相同 CAN 波特率和采样点
- 主机应烧录 `Debug-Master`
- 从机应烧录 `Debug-Slave`
- 正常测试不要烧录回环测试固件
